# loomark v2.4.4 Social Copy

## Chinese

loomark 2.4.4 已发布。这一版里有一条是真问题，其余几处是挡路的。

- **带 YAML frontmatter 的笔记不再被改写**：这类笔记的开头是一段属性区（title、tags、aliases 这些）。以前打开它、一个字都不改直接保存，这段就会被重排成非法 YAML，属性面板、标签检索、Dataview 会跟着一起失效。现在这块内容不进编辑器，保存时按字节原样写回。谢谢把最小复现样本和前后对比一起发来的那位朋友
- **CRLF 的文件保存后还是 CRLF**：以前会被整份改写成 LF，Windows 上编辑过的文件在 git 里显示整篇都变了
- **导出 PDF 时表格不再丢掉最后一列**：单元格里不能换行的长内容（JSON、长链接）会把表格撑出纸面，现在打印时这些长 token 会断行
- **查找替换框不再被右上角的按钮压住**：它以前正好落在窗口按钮那一行里，Windows 上尤其明显
- **从 Finder 打开文件会落进你正在看的窗口**：以前可能送进后面那个空白窗口，表现出来就像文件根本没打开
- **文件列表可以放到左侧**：视图菜单里二选一，默认在右边，顶行的形状和三个按钮都不动

免费、开源，文件永远是最新的。

## English

loomark 2.4.4 is out. One of these was a real problem; the rest were in the way.

- **Notes with YAML frontmatter survive a save**: that block at the top of a note (title, tags, aliases) used to be reflowed into invalid YAML by opening the file and saving it, without editing anything, which quietly broke the properties panel, tag search and Dataview in the vault it came from. It now stays out of the editor and is written back byte for byte. Thank you to the person who sent the minimal sample and the before and after
- **A CRLF file stays CRLF**: it used to be rewritten to LF from top to bottom, so an edited file showed up as a whole-file change in git on Windows
- **A PDF export stops dropping a wide table's last column**: one unbreakable token in a cell (JSON, a long URL) set a minimum width the table could not go below. Long tokens now break when printing
- **The find panel is no longer covered by the window buttons**: it used to sit inside the top row, right where those buttons are drawn
- **A file opened from Finder lands in the window you are looking at**, instead of one sitting behind it, which looked like the file never opened
- **The file list can sit on the left**: View menu, either side, right by default. The top row and its three buttons do not move

Free, open source, and your files are always current.
